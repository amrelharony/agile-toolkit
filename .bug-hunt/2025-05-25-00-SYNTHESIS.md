# Phase 0-4 deep bug audit — synthesis (2026-05-25)

**Scope:** all code introduced or touched by the five Phase 0-4 commits (history multi-author, squads, session_invites, canvas multiplayer, planning-poker multiplayer) — landing on top of the May-24 audit baseline (`BUG_REPORT.md`).

**Method:** 12 parallel deep-dive agents, one per surface, plus a manual side-channel pass. Each agent re-read every cited file before flagging anything. Baseline: 90/90 vitest, clean lint (warnings only), production build passes.

**Per-area reports:** `.bug-hunt/2025-05-25-{01..12}-*.md` (and `99-manual-findings.md`).

---

## TL;DR — the four bugs to fix before merge

1. **[CRITICAL]** Planning Poker host can be impersonated by any peer holding the room code, because `senderIsHost` is computed from two attacker-controlled fields in the same payload. `use-poker-session.ts:83-85`.
2. **[CRITICAL]** Planning Poker guests apply ANY validated `poker:state` wholesale — there is no merge defence on the guest side. Any peer can flip `revealed: true` pre-reveal, rewrite stories, or change `hostId`. `use-poker-session.ts:84-85`.
3. **[HIGH]** Cross-tool authorization leak: the guest-log API's squad-level fallback (when `entityId` is omitted) picks the most-privileged invite ACROSS tool_ids. A canvas-editor guest can write `vote_cast` rows under `planning-poker` etc. `api/guest/log/route.ts:132-155` + `use-history-logger.ts:115-127`.
4. **[HIGH]** Canvas activity author is permanently `"Anonymous"` — Phase 3's whole intent never works. The display name is not threaded through to `useCanvasPresence`. `whiteboard-canvas.tsx:317` + `use-canvas-presence.ts:165`.

## Cross-cutting themes

1. **Identity isn't authenticated end-to-end.** The Supabase realtime channel doesn't sign broadcast envelopes. Multiple bugs (C1, C2, H6) all reduce to "the receiver trusts a string the sender chose." Every consumer of `room.broadcast` needs to either (a) cross-check `env.by` against `room.members` AND a server-side trust anchor (e.g. the locally-known `hostId`), or (b) stop trusting any field that overlaps with `env.by`.
2. **The owner tree is missing `PresenceIdentityProvider`.** Three independent agents (02, 06, 11) flagged variations of "owner is `Player NNN` in their own activity log / presence / canvas cursors." Fix is mechanical — wrap `AppShell` in a `PresenceIdentityProvider` populated from `AuthProvider`'s user.
3. **`agile-toolkit:workspace` localStorage is shared across owner and guest tabs.** Phase 0-4 took care to avoid clobbering `agile-toolkit:user`, but `agile-toolkit:workspace` is written by both modes (whiteboard objects, activity log, more). H4 + H5 are the visible symptoms; the underlying primitive (workspace-store persisting under a non-mode-scoped key) needs either per-mode key suffixes or a sign-out sweeper.
4. **Per-tool authorization should not be per-role-only.** H1 is the cross-tool authz leak; the action allowlist is per-role only. Action × tool_id should be the matrix, not action × role.
5. **`expires_at` / `revoked_at` semantics are inconsistent.** H14 + H15 + M16 + M17 + M18 are all variations of "the schema has the column but only some code paths consult it."

## What didn't break

Big wins that the audit explicitly verified:

- **`subscribeToEvent` Map iteration fix is real.** Pre-Phase-2 the Map was populated but never iterated. Confirmed via `git show 584c948:src/lib/realtime/use-room.ts`. Canvas multiplayer worked single-tab-only before; now flows.
- **HMAC cookie signing is correct.** Per-row `cookie_secret`, `timingSafeEqual` on equal-length buffers, UUID-validated profile id before DB lookup, `revoked_at` checked on every resolve.
- **Squad-code entropy is 192 bits** (`randomBytes(24).base64url`). Collision-free for practical purposes.
- **RLS is owner-only with `to authenticated` explicit grants and `to anon` revokes** on every new table; service-role guest path is the explicit boundary the design relies on.
- **PostgREST `.or().or()` chaining** in `listInvitesForGuest` produces the intended AND-of-ORs (verified against `postgrest-js` source).
- **`isSafeGuestNextUrl`** rejects absolute URLs, `//`, `\\`, encoded-host, and restricts to `/guest/` prefix.
- **`coalesce(profile_id, sentinel UUID)`** defeats the NULL-distinctness footgun in the session_invites partial unique index.
- **The diff-sync reset-before-apply order in canvas** correctly prevents inbound-echo loops.
- **`isValidSession` caps are enforced at the only entrypoint** and survive end-to-end through the merge.
- **The display-name sanitizer covers the high-impact invisibles** (C0/DEL, bidi overrides, zero-widths, BOMs) and NFC-normalises.

## Process / methodology notes

- The May-24 audit (`BUG_REPORT.md`) noted that ~70% of agent "Critical/High" findings were false positives. The 2026-05-25 run was tighter — verified-true rate is higher because (a) agents had narrower scopes, (b) every finding cites file:line and was re-verified against the inline-comment fix-history, (c) the Phase 0-4 commits are recent enough that the code is genuinely under-defended in places the May-24 audit couldn't have seen.
- Multiple agents converged on H2/H3 (owner-identity) and H16/M19 (squad code shape + display-name uniqueness). Convergence = high confidence.
- Per-area reports include "Open questions" sections — most of those are design decisions the user should weigh in on rather than bugs.
- 90 vitest tests pass. Coverage is ~45% statements, weakest in `lib/actions/server-store.ts` (5% — MCP write path) and `lib/history/sync.ts` (4% — owner sync engine). The Phase 0-4 changes have validator-only test coverage (`session-validator.test.ts`, `squad-display-name.test.ts`, `guest-session-signing.test.ts`); no integration tests for the realtime broadcast paths, the merge logic, the guest-log API, or the resolveGuestInvite chain. **Recommend adding integration tests for the four critical/high findings before fixing them — so the fix is locked in.**
